# **C Project \- Lego Tiling Generator (img2brick)**

This C module serves as the calculation engine for the project. It takes a pixel matrix (in hexadecimal format) and a brick catalog as input, generating two tiling proposals (1x1 and Quadtree. Additionally, the Tiler also creates a file containing the missing bricks (if any) for each algorythm, it makes communication with the C component easier

## **Compilation**

The project has no external dependencies beyond the standard C library (stdlib, stdio, string, math).

gcc \-o img2brick  .\\img2brick.c

## **Usage**

The program expects 3 arguments:

./img2brick \<image\_file\> \<catalog\_file\> \<variance\_threshold\>

* \<image\_file\>: Text file containing dimensions and the hexadecimal pixel matrix.  
* \<catalog\_file\>: Text file generated by the Java backend containing stock and prices of each brick.  
* \<variance\_threshold\>: Integer (ex. 2000). Higher values use larger bricks (cheaper, less detailed). Lower values produce finer details.

***NOTE :** I found after some testing that the  threshold sweet spot is around 2000-4000-ish for midrange images (100-200px dimensions)*

## **Outputs**

The program generates the following files in the current directory:

1. tiled\_quadtree\_image.txt: List of bricks with their name, size and position. V3 algorithm in the context of this project.  
2. Tiled\_1x1\_image.txt: Same as above V1 algorithm, slower than V3.  
3. invoice\_quadtree.txt: missing stock for the optimized version.  
4. invoice\_1x1.txt: Same as above for the 1x1 version.
